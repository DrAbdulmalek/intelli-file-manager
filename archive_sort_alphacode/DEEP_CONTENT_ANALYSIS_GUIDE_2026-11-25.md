# دليل التحليل العميق للمحتوى عند الفرز (وضع --deep)

**التاريخ**: 2026-11-25 · **الالتزام**: `f8f7500` على فرع `feat/archive-sort-unified-decision`
**طلب المالك**: «تطبيق الفرز يقرأ محتوى الملف عند فرزه، ولاحقًا يحلل الصور لفرزها وكذلك الأصوات وكل ما يلزم» — نُفِّذ بالكامل ومحلي 100%.

## 1. ما أُضيف (بالضبط)

| القدرة | التفاصيل | التقنية (محلية) |
|---|---|---|
| **قراءة محتوى المستندات** | نص عادي (txt/md/csv/log/json/xml/كود…)، PDF، Word (docx)، ODT، PPTX، XLSX، EPUB — ثم استنباط **لغة المحتوى** (عربي/إنجليزي/مختلط) و**نوع المستند**: فاتورة، عقد، شهادة، سيرة ذاتية، بحث، تقرير، كتاب، محاضرة، رسالة | قراءة مباشرة + `pypdf`→`PyMuPDF` + `python-docx` + `zipfile` |
| **تحليل الصور** | الأبعاد ونسبة العرض، **EXIF الكاميرا** (الصانع/الموديل/الوقت)، **كشف لقطات الشاشة** (نمط الاسم أو بلا EXIF + أبعاد شاشة)، **الألوان السائدة**، صور رمادية، وتصنيف: `screenshot` / `camera_photo` / `photo` | `Pillow` |
| **تحليل الصوتيات** | المدة، معدل البت، معدل العينات، **وسوم ID3** (عنوان/فنان/ألبوم/نوع)، وتمييز **موسيقى** (وسوم فنان/ألبوم) مقابل **تسجيل صوتي** (بلا وسوم + مدة/امتداد هاتف) | `mutagen` — **بلا حاجة لـ ffprobe** |

## 2. كيف يعمل داخل محرك الفرز

1. عند تمرير `--deep` يُثرى كل سجل ملف بعد مسحه: `extra_metadata` (مثل `image_kind`, `width`, `duration_seconds`, `content_lang`, `doc_type`) + **وسوم**: `screenshot`، `camera-photo`، `music-tagged`، `voice-recording`، `grayscale-image`، `deep:ar`/`deep:en`، `doc:<النوع>`.
2. إصلاح مصاحب مهم: شرط **`has_tag` في محرك القواعد كان معطّلًا** (يفحص مفتاحًا لا يضخه أحد) — الآن يعمل، فتستطيع القواعد التوجيه بالوسوم.
3. **قواعد الفرز الفرعي للوسائط أُضيفت معطلة** (بانتظار اعتمادك): لقطات الشاشة→`وسائط/لقطات_شاشة`، صور الكاميرا→`وسائط/صور_كاميرا`، الموسيقى→`وسائط/موسيقى`، التسجيلات→`وسائط/تسجيلات_صوتية`. ما لم تفعّلها تبقى الوسوم توثيقًا في التقرير دون تغيير وجهات (تفعيلها ينشئ مجلدات فرعية داخل وسائط = توسيع للقرار الموحد يحتاج قرارك البندي).
4. عدادات `deep_analysis` تظهر في ملخص JSON وسطر ملخص المسح في التقرير.

## 3. الأمان والخصوصية (غير قابلة للتفاوض)

- **الحاجز أولًا**: الملف الحساس (`is_sensitive_path`) لا يُفتح محتواه إطلاقًا — يُوسم `sensitive-no-deep` ويُتخطى. المحتوى الطبي في وضع strict محجوب كذلك.
- **محلي بالكامل**: لا شبكة، لا API خارجي، لا OCR سحابي — متسق مع سياسة النطاق في WORKLOG («لا API خارجي في قرارات الأرشيف»).
- **حدود أحجام**: نص ≤20MB، صورة ≤80MB، صوت ≤500MB (قراءة رأس فقط) — التجاوز تخطٍ لا فشل.
- **عزل الأخطاء**: كل ملف في `try/except` مستقل — ملف تالف لا يوقف المسح.

## 4. الأوامر (على جهازك)

```bash
# 0) لمرة واحدة: متطلبات التحليل العميق
pip install -r requirements-deep.txt

# 1) تحديث الفرع
git pull origin feat/archive-sort-unified-decision

# 2) تجربة على شجرة فرعية أولاً (مستحسن قبل القرص الكامل):
python3 archive_sort_alphacode/scripts/archive_sort.py \
    --root "/run/media/xorthomson/My Passport/Lenovo laptop" \
    --fast --deep \
    --out archive_sort_alphacode/LOGS/dry_run_deep_pilot.html

# 3) المسح الكامل بالتحليل العميق (ساعات عدة على fuseblk — دفعة تجريبية أولاً):
python3 archive_sort_alphacode/scripts/archive_sort.py \
    --root "/run/media/xorthomson/My Passport" \
    --fast --deep \
    --out archive_sort_alphacode/LOGS/dry_run_report_v3_deep.html
```

وضع `--deep` يعمل أيضًا مع سكريبت التنفيذ الآمن `scripts/archive_sort.py` (مع `--execute --confirm-execute` وفق بوابات الخطة).

## 5. سير اعتماد الفرز الفرعي (بعد مراجعة تقرير الـdeep)

1. راجع التقرير: عدادات التحليل + توزيع الوسوم (كم لقطة شاشة؟ كم تسجيل؟).
2. إن أجبتَ «نعم» على المجلدات الفرعية الأربعة: افتح `archive_sort_alphacode/rules/archive_sort_rules.yaml` وبدّل `enabled: false` → `true` للقواعد الأربع في قسم (8).
3. أعد توليد التقرير وراجع الوجهات الجديدة، ثم اعتمد بنديًا كالمعتاد قبل أي تنفيذ.

## 6. التحقق المنجز

- **13 اختبارًا جديدًا** (`tests/unit/test_content_analyzer.py`): استخراج عربي/PDF/docx، كشف لقطة شاشة، EXIF كاميرا، ألوان سائدة، مدة WAV، **الحاجز يمنع قراءة الملف الحساس**، شروط `has_tag`/`extra`.
- **البوابة الكاملة**: 788 passed / 1 skipped (كانت 775).
- **اختبار دخان طرف-للطرف** عبر السكريبت الفعلي: لقطة شاشة وُجِّهت بقاعدة `has_tag` المفعلة مؤقتًا إلى `وسائط/لقطات_شاشة`، وملفات `.git` وُسمت **دون نقل**، والفاتورة والعقد حُددا من محتواهما، و`.git/config` (بلا امتداد) تُسقط بأمان في `unsupported`.

## 7. الأداء المتوقع

التحليل يفتح رأس كل ملف وسائط/مستند: ≈112 ألف صورة + ≈11.7 ألف صوت + المستندات على قرص fuseblk = **ساعات عدة** في المسح الكامل. لذا المسار الموصى به: شجرة فرعية → مراجعة → مسح كامل بين وقتين، والنقل الفعلي يبقى ببوابات الخطة المعتمدة (نسخة البصمات ×2، الدفعة التجريبية 200–500، البند 4).
