# سياسة النطاق — فرز الأرشيف (ناتج عمل AlphaCode)

> ملزمة لجميع قرارات فرز الأرشيف في هذا المشروع.

## القاعدة

**لا يُستخدم أي API خارجي (LLM أو غيره) في قرارات فرز الأرشيف.**

القرارات تُبنى حصراً على:
1. **أدلة الكود** (سلوك SafeMover، path_policy، tree_manifest، إلخ).
2. **تقرير المحاكاة** (`dry_run_report.html` بالوضع الكامل).
3. **قرارات المالك** (البنود المفتوحة).
4. **القرار الموحد** (`القرار_الموحد_لفرز_الأرشيف.docx`).

## لماذا

- المشروع **local-first**؛ إرسال بيانات وصفية (أسماء ملفات/قواعد/مجلدات)
  إلى خدمة خارجية يناقض الفلسفة ويشكّل تسريباً وصفياً.
- النماذج الخارجية لا تملك وصولاً للكود ولا القرص ولا التقرير، فرأيها
  "إعادة صياغة عامة" لا "دعم قرار".
- أي استشارة خارجية = **انتهاك نطاق**، تُوثَّق كحادثة (انظر
  `INCIDENT_external_LLM_consultation.md`) لا كدعم قرار.

## المفتاح المكشوف

مفتاح Vyce AI الذي أُرسل في المحادثة **مكشوف** ويجب تدويره فوراً
(revoke + إصدار جديد). لا يُستخدم مستقبلاً.
