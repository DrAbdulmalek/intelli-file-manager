# ADR-0001: سياسة التضارب في الوجهة — لاحقة إلزامية ورفض overwrite مطلق

- **الحالة:** مقبول
- **التاريخ:** 2026-11-20
- **القرار منذ:** إصلاحات P0 الأولى (`be77e5f` وما بعدها — PR #66)
- **توثيق رسمي بناء على:** بند P1/P5 من جلسات المراجعة المستقلة (DeepSeek) — «القرار يجب توثيقه في ADR مع اختبار صريح لرفض overwrite»
- **السياق:** PR #66 (`fix/p0-safe-mover-and-barrier`)، ذو صلة بـPR #63 (الحاجز الحساسي)

## السياق

عند نقل/نسخ ملف إلى وجهة موجودة، كانت الواجهات القديمة تعتمد `os.replace` /
`shutil` الذي **يستبدل صامتاً** — فقدان بيانات بلا أثر. وجدت مراجعات مستقلة
(AlphaCode، ChatGPT، DeepSeek — 11 جولة موثقة في `docs/alpha-session-2026-11-20/`)
أن هذه النقطة هي الأخطر في طبقة الملفات: المستخدم قد يفقد تقريراً طبياً
لأن مجلد الوجهة فيه ملف بنفس الاسم.

## القرار

1. **لا استبدال صامت أبداً:** التضارب يُحل بإلحاق لاحقة تصاعدية
   `report_1.txt`, `report_2.txt`, ... عبر `_resolve_collision`
   (`src/core/safe_mover.py:180`). الشاغل الأصلي يبقى سليماً بمحتواه الكامل.
2. **`overwrite=True` محظور مطلقاً:** تهيئة `SafeMover(overwrite=True)`
   ترفع `OverwriteForbiddenError` فوراً (`safe_mover.py:417` مثلاً)،
   ومَن يمرر `overwrite` في أي مستوى أعلى يُرفض صراحة — بما في ذلك
   طبقة MCP (`src/mcp_server/server.py`: معامل `overwrite` غير موجود
   في `safe_move_file` وتمريره يعيد رسالة رفض توثيقية).
3. **التراجع يمر عبر نفس العقد:** `UndoLog.rollback_last` يعيد الملف
   عبر SafeMover — إن كان الموضع الأصلي مشغولاً الآن، يأخذ التراجع لاحقة
   ولا يستبدل الشاغل (إغلاقات ما بعد `fe9e643`).
4. **no-op محدد بدقة:** النقل إلى نفس المسار المحلول
   (`src.resolve() == dst.resolve()`) ينجح idempotent بلا لاحقة
   (`safe_mover.py:477`). المسارات المكافئة عبر الروابط (symlink للوجهة
   نفسها) تُعالج بنفس الحارس؛ الـhardlink (نفس الـinode بمسارين مختلفين)
   **ليس** no-op بالتعريف الحالي — يأخذ لاحقة ويحفظ الطرفين، **بلا فقد
   بيانات** (موثق باختبارات `tests/unit/test_safe_mover_nop_guard.py`).

## البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| استبدال صامت (`os.replace` كما كان) | فقد بيانات بلا أثر — الخطورة القصوى |
| رفض العملية عند أي تضارب | يجمّد سير العمل؛ المستخدم يلجأ لأدوات خارجية أخطر |
| `overwrite` كخيار اختياري افتراضي False | خيار واحد خاطئ يفقد البيانات؛ السطح غير ضروري لأن اللاحقة تحل الحالة |
| كشف no-op بالـinode (hardlink) | يحتاج `os.stat` إضافياً في المسار الساخن؛ اللاحقة تحفظ البيانات أصلاً — القرار قابل للمراجعة إن طلب الاستخدام |

## العواقب

- **إيجابية:** صفر حالات فقد بيانات بتضارب الأسماء عبر كل المسارات
  (move/copy/undo/rule_engine/MCP)؛ سلوك متوقع وقابل للفحص البصري
  (`used_suffix=true` في مخرجات MCP).
- **تكلفة:** قد تتعدد الملفات الملحقة عند تكرار النقل لنفس الوجهة —
  مقصود: الأثر مرئي وقابل للتنظيف يدوياً واعياً.
- **اختبارات العقد:** `test_safe_mover_p0_closures.py` (سيناريو الشاغل)،
  `test_safe_mover_nop_guard.py` (symlink/hardlink/تهجئة المسار)،
  `test_mcp_feedback.py::test_safe_move_file_rejects_overwrite_parameter_by_design`.
